# 구매가치와 단기 미구매 위험을 결합한 CRM 우선점검 설계

`Retail CRM Priority Design`

> **핵심 질문:** 모든 고객을 동일하게 관리하기 어렵다면, **구매기여가 큰 고객 중 누구부터 확인해야 하는가?**
>
> **핵심 결론:** 최근 26주 구매금액 상위 20% 고객을 먼저 정의한 뒤, 그 안에서 다음 4주 미구매 위험 상위 10%를 우선점검 대상으로 선정했습니다. Test 91~98주 합산 기준 가치고객 미구매 86건 중 65건(75.6%)이 이 Priority 집단에 포함되었습니다.

---

## 1. 왜 이 프로젝트를 시작했는가?

누적 구매금액이나 마지막 구매일 하나만으로는 **회사에 중요한 고객**과 **최근 구매가 약해진 고객**을 동시에 구분하기 어렵습니다.

또한 미구매 위험이 높다는 이유만으로 모든 고객에게 같은 CRM 비용을 쓰는 것도 실제 운영 목적과 맞지 않을 수 있습니다.

그래서 프로젝트의 질문을 다음과 같이 정의했습니다.

```text
누가 구매하지 않을 가능성이 높은가?
+
누가 회사에서 구매기여가 큰가?
↓
누구부터 CRM 담당자가 확인할 것인가?
```

예측모델 자체가 최종 목적이 아니라, **매주 CRM 담당자가 먼저 확인할 고객을 HOUSEHOLD_KEY 단위로 좁히는 기준**을 만드는 것이 목표입니다.

---

## 2. 실제 운영에서는 어떻게 사용할 수 있는가?

이 프로젝트는 분석 결과를 실제 주간 CRM 업무에 연결하는 상황을 가정했습니다.

```text
매주 고객행동 업데이트
↓
다음 4주 미구매 위험 계산
↓
최근 26주 구매금액 상위 20% 선정
↓
그 안에서 위험 상위 10% 선정
↓
HOUSEHOLD_KEY 기준 약 50가구 Priority 생성
↓
CRM 담당자가 최근 활동과 관계상태를 확인
↓
실제 캠페인 여부 결정
```

즉 모델이 자동으로 `쿠폰 발송`까지 결정하는 구조가 아니라, **한정된 CRM 인력과 비용 안에서 누구부터 사람이 확인할 것인지 좁혀주는 의사결정 기준**입니다.

Test 91~98주에 같은 기준을 반복 적용했을 때 가치고객 미구매 86건 중 65건(75.6%)이 Priority 집단에 포함되어, 실제 운영을 가정한 우선점검 기준으로 활용할 가능성을 확인했습니다.

---

## 3. 이 프로젝트에서 가장 중요했던 판단

처음 기대한 결과가 나오지 않았을 때 원하는 결과를 만들기 위해 cutoff를 바꾸지 않았습니다.

```text
위험모델은 작동함
↓
그러나 RFM 고가치 × 전체 고위험 교집합 0
↓
왜 그런지 진단
↓
RFM 가치와 위험모델이 최근성·빈도 정보를 공유함을 확인
↓
예측위험과 경제적 구매가치의 역할을 분리
↓
가치고객 안에서 상대 위험순위를 적용
↓
HOUSEHOLD_KEY 단위 CRM 우선점검 기준 완성
```

이 프로젝트의 최종 결과는 높은 모델 점수 자체가 아니라, **분석결과를 보고 비즈니스 목적에 맞게 기준을 수정하고 실제 운영 가능한 고객 리스트까지 연결한 과정**입니다.

## 4. 데이터와 분석 단위

- **Dataset**: dunnhumby - The Complete Journey
- **핵심 사용 파일**: `transaction_data.csv`, `product.csv`
- **가구 수**: 2,500가구
- **관찰 기간**: 약 2년
- **모델링 단위**: 가구 × 기준주차
- **예측 대상**: 기준주차 이후 **다음 4주 동안 구매가 한 번도 없는지**

### 표현 원칙

이 프로젝트의 `다음 4주 미구매`는 **영구 이탈(Churn)** 이 아닙니다.

관찰기간 밖의 구매나 다른 소매점 이용을 알 수 없기 때문에, 결과는 **단기 미구매 위험** 또는 **CRM 우선점검 후보**로 표현합니다.

## 5. 분석 설계

### 5.1 고객 행동 창

```text
최근 26주
→ 장기 구매습관과 구매기여 확인

직전 4주 vs 최근 4주
→ 구매활동 변화 확인

기준주차 이후 4주
→ 실제 미구매 여부 확인
```

초기 분석에서는 RFM, 최근 활동변화, 고객상태를 구성하고 상태별 이후 구매지속률을 비교했습니다.

그 과정에서 **구매 감소율이 크다고 해서 항상 다음 4주 미구매 위험이 높은 것은 아니었다**는 점을 확인했습니다. 따라서 단순 감소 규칙 대신 장기 구매습관과 최근 실제 활동량을 함께 사용하는 예측 단계로 확장했습니다.

### 5.2 시간순 검증

무작위 행 분할 대신 실제 운영과 비슷하게 시간을 순서대로 분리했습니다.

```text
Train       26~74주
Gap         75~78주
Validation  79~86주
Gap         87~90주
Final Test  91~98주
```

Gap은 기준주차 이후 4주 라벨이 다음 구간과 겹치는 문제를 줄이기 위해 두었습니다.

Final Test는 모델 선택에 사용하지 않고, Validation에서 모델과 기준을 고정한 뒤 마지막에 한 번 평가했습니다.

## 6. 어떤 정보가 미구매 예측에 도움이 되었는가?

Feature Set을 단계적으로 추가해 어떤 정보가 실제 예측에 기여하는지 확인했습니다.

| Feature 단계 | Validation PR-AUC | 해석 |
|---|---:|---|
| 최근 구매시점 중심 | 0.5595 | Recency만으로도 일정 수준 구분 가능 |
| 장기 RFM 추가 | 0.6177 | 장기 구매습관이 큰 추가정보를 제공 |
| 최근/직전 절대 활동 추가 | 0.6263 | 최근 실제 구매량을 함께 볼 때 개선 |
| 변화량·변화율 추가 | 0.6271 | 추가 개선은 약 0.0008로 매우 작음 |
| 전체 구매행동 | 0.6368 | 구매일수·구매주차수 등 습관 구조가 추가 기여 |
| 고객상태 추가 | 0.6375 | 설명에는 유용하지만 추가 예측정보는 제한적 |

### 핵심 인사이트

**몇 % 감소했는가**보다 **현재 실제로 얼마나 구매하고 있는가 + 장기적으로 어떤 구매습관을 가졌는가**를 함께 보는 것이 더 유용했습니다.

고객상태는 사람이 이해하기 위한 설명용 세그먼트로, 모델 확률은 고객을 세밀하게 정렬하는 우선순위용으로 역할을 분리했습니다.

## 7. Logistic Regression을 최종 모델로 선택한 이유

Validation에서 Logistic Regression과 XGBoost를 비교했습니다.

| 모델 | PR-AUC | 위험 상위 10% 실제 미구매율 |
|---|---:|---:|
| Logistic Regression | 0.6375 | 72.9% |
| XGBoost | 0.6426 | 72.1% |

XGBoost가 전체 PR-AUC에서는 소폭 높았지만 차이는 약 0.005였습니다.

반면 실제 CRM에서 상위 고객만 확인하는 시나리오에서는 Logistic Regression이 유사하거나 소폭 우수했고, 결과를 운영 담당자에게 설명하기도 더 쉬웠습니다.

따라서 **복잡도 대비 개선폭이 제한적이라고 판단해 Logistic Regression을 최종 모델로 고정**했습니다.

## 8. Final Test: 더 미래에서도 위험순위가 작동하는가?

모델 선택에 사용하지 않은 91~98주에서 마지막으로 확인했습니다.

| 항목 | Final Test 결과 |
|---|---:|
| 전체 실제 다음 4주 미구매율 | 19.45% |
| 위험 상위 10% 실제 미구매율 | 70.85% |
| Lift@10% | 3.64배 |
| PR-AUC | 0.6212 |
| ROC-AUC | 0.8830 |
| Brier Score | 0.1034 |

즉 무작위로 고객을 확인하면 약 19%가 실제 미구매였지만, 모델이 위험 상위로 정렬한 집단에서는 약 71%가 실제 다음 4주 미구매였습니다.

Calibration도 10개 구간 기준 예측확률과 실제 미구매율의 평균 절대 차이가 약 1.2%p로 비교적 안정적으로 유지되었습니다.

### 해석

이 결과는 모델이 고객을 자동으로 재활성화한다는 뜻이 아닙니다.

**모든 고객을 동일하게 보지 않고, 먼저 확인할 고객 순서를 만드는 데 활용할 수 있는가**를 확인한 결과입니다.

## 9. 첫 번째 CRM 설계는 왜 실패했는가?

처음에는 아래처럼 생각했습니다.

```text
RFM 고가치
+
전체 미구매 위험 상위 10%
→ CRM 최우선 점검
```

하지만 98주에서 실제 결과는 다음과 같았습니다.

- 전체 고객: 2,500가구
- RFM 고가치: 418가구
- 전체 위험 상위 10%: 250가구
- **RFM 고가치 + 고위험 교집합: 0가구**

### 원인

RFM 가치에는 `Recency + Frequency + Monetary`가 포함되어 있었고, 미구매 예측모델도 최근성·빈도·최근 활동을 강하게 사용했습니다.

따라서 두 축이 독립적인 가치와 위험을 나타내기보다 같은 정보를 일부 공유하면서 강한 반대관계를 만들었습니다.

이 단계에서 얻은 중요한 결론은 다음과 같습니다.

> **예측위험이 높다는 것과 회사가 먼저 관리해야 할 고객이라는 것은 같은 문제가 아니다.**

원하는 교집합을 만들기 위해 cutoff를 사후 조정하거나 모델을 다시 튜닝하지 않았습니다.

## 10. CRM Business Layer 재설계

예측모델은 그대로 유지하고 **가치의 정의만 경제적 구매기여로 분리**했습니다.

### 기존

```text
RFM 가치 = Recency + Frequency + Monetary
```

### Revised

```text
경제적 구매기여 = 최근 26주 구매금액
```

그리고 Value First → Risk Ranking 방식으로 운영 규칙을 만들었습니다.

```text
전체 2,500가구
↓
최근 26주 구매금액 상위 20%
↓
500가구
↓
그 500가구 안에서 미구매 위험 상위 10%
↓
HOUSEHOLD_KEY 기준 50가구
↓
CRM 우선점검 후보
```

## 11. Week 98 운영 시뮬레이션

98주에서 동일한 규칙을 적용한 결과입니다.

| 구분 | 결과 |
|---|---:|
| 구매기여 상위 고객 | 500가구 |
| CRM Priority | 50가구 |
| 가치고객 전체 실제 미구매 | 12가구 |
| Priority 내 실제 미구매 | 9가구 |
| 가치고객 전체 미구매율 | 2.4% |
| Priority 미구매율 | 18.0% |
| 가치고객 대비 Lift | 7.5배 |
| 가치고객 미구매 포착률 | 75.0% |

중요한 비교는 전체 고객 20.36%와 Priority 18.0%가 아닙니다.

이 전략의 목적은 **전체에서 가장 위험한 고객을 찾는 것**이 아니라, **구매기여가 큰 고객들 중 상대적으로 주의할 고객을 찾는 것**입니다.

따라서 같은 가치고객 집단의 2.4%와 Priority의 18.0%를 비교합니다.

## 12. 91~98주에 같은 기준을 반복하면?

98주 한 번의 우연인지 확인하기 위해 기준을 바꾸지 않고 91~98주 각 기준주차에 같은 규칙을 반복 적용했습니다.

### 8주 합산 결과

| 구분 | 결과 |
|---|---:|
| 구매기여 상위 고객 | 4,000 가구×주차 |
| CRM Priority | 400 가구×주차 |
| 가치고객 실제 미구매 | 86건 |
| Priority에서 포착 | 65건 |
| 가치고객 전체 미구매율 | 2.15% |
| Priority 미구매율 | 16.25% |
| 가치고객 대비 Lift | 7.56배 |
| 가치고객 미구매 포착률 | 75.6% |

각 주차에서도 Priority 미구매율은 14~18%, 가치고객 전체는 1.8~2.6% 수준으로 같은 방향이 유지되었습니다.

### 해석 시 주의

91~98주의 미래 4주 평가구간은 서로 일부 겹치며, 같은 HOUSEHOLD_KEY가 여러 주에 반복 등장합니다.

따라서 **8번의 완전히 독립된 실험에서 모두 성공했다**고 표현하지 않습니다.

정확한 표현은 다음과 같습니다.

> Test 기간 내 연속된 여러 기준시점에서 같은 CRM 규칙을 반복 적용했을 때 일관된 방향의 선별효과가 나타났다.

## 15. 해석 범위와 다음 검증

현재 결과는 **CRM 담당자가 먼저 확인할 후보를 얼마나 효율적으로 좁힐 수 있는지**를 검증한 Backtest입니다.

실제 캠페인을 실행한 데이터는 없기 때문에 재구매 증가나 매출 개선 같은 **개입 효과 자체를 입증한 것은 아닙니다.** 실제 효과를 평가하려면 향후 Holdout 또는 A/B Test가 필요합니다.

또한 `다음 4주 미구매`는 영구 이탈이 아니며, 91~98주의 평가구간은 일부 겹치므로 완전히 독립된 8회 실험으로 해석하지 않습니다.
